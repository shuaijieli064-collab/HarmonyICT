## 二、范围收敛：做什么、不做什么

ChatGPT 原方案（六大引擎 + 个人世界模型 + 完整 Agent）超出 3 人 + 比赛周期承载能力。比赛版收敛如下：

| 保留（比赛必做） | 砍掉（长期愿景，不进去年） |
| --- | --- |
| 个人世界模型（精简：实体 / 事实 / 事件 / 来源） | 六大业务引擎全部独立上线 |
| 主动风险发现（期限、冲突、到期、预算 4 类） | 多方案决策模拟（模块 C，复杂且非得分点） |
| Agent 执行（L2：授权后创建待办 / 更新记录） | 自动支付、交易、第三方账户操作 |
| 文件接入 + AI 结构化抽取（PDF / 图片 / TXT） | 实时环境感知、视频理解、智能家居控制 |
| 可视化驾驶舱（ Dashboard + 风险 + 世界模型 + Agent） | 跨平台账户自动接入、完整视频实时理解 |

**收敛后的一句话定位：NEXUS 是一个「个人资料智能管家」——上传资料，AI 抽取成结构化事实，系统主动发现风险，授权后生成行动。**

## 三、唯一核心闭环（Demo 主线）

所有开发服务于这一条能完整演示的闭环：

```
用户上传凭证/资料(PDF/图片/TXT)
        ↓  OBS 存原文件
华为云 OCR + MaaS 大模型抽取结构化信息
        ↓
写入 RDS(PostgreSQL)：实体 / 事实 / 事件 / 来源
Redis 缓存风险状态与任务状态
        ↓
前端可视化：世界模型图谱 + 时间线 + 风险中心
        ↓
系统展示风险（含触发规则与证据来源）
        ↓
用户授权 → Agent 生成待办 / 更新记录 → 留存执行日志
        ↓
前端展示执行结果，世界模型更新
```

**演示故事**：大学生上传笔记本发票、订阅记录、学习计划 → 系统抽取出设备、购买日期、保修期、预算、目标 → 展示个人世界模型 → 发现「订阅即将续费」「任务与目标期限冲突」风险 → 授权 Agent 创建待办 → 展示执行结果。

## 四、技术架构（对齐华为云）

| 层 | 选型 | 华为云产品触点 |
| --- | --- | --- |
| 前端 | Next.js + React + TypeScript + Tailwind + ECharts | 部署在华为云（公网访问） |
| 后端 | Java 21 + Spring Boot + Spring Security + JWT | CodeArts 构建 / 部署；模块化单体，不拆微服务 |
| 数据库 | PostgreSQL（业务数据 + 世界模型） | **RDS for PostgreSQL（Skills 开通）** |
| 缓存 | Redis（任务状态、风险状态、会话） | **Redis 云服务（Skills 开通）** |
| 文件 | OBS（原始文件 / 图片） | **OBS** |
| AI | 大模型推理 + OCR + 结构化输出 | **华为云 MaaS / 模型推理服务，统一封装 AI Provider 接口** |
| 研发工具 | CodeArts 代码智能体（必选） | 需求 / 编码 / 修复 / 构建 / 部署全流程 |

核心数据表（精简）：`users`、`world_entities`、`world_facts`、`world_sources`、`world_events`、`world_risks`、`tasks`、`agent_runs`、`agent_action_logs`。所有业务表带 `user_id` 做数据隔离。

## 九、关键原则

1. **评分点优先**：任何功能若不能支撑「华为云产品价值」或「完整闭环」，先不做。
2. **证据留痕**：CodeArts 操作、云服务开通、部署过程全程截图/录屏，答辩直接用。
3. **规则支撑智能**：风险判断由规则/算法给出，大模型只做理解与解释，不用随机结论。
4. **授权边界**：仅 L0-L2（读取/建议/内部操作需确认），不开放支付与外部高风险操作。
5. **并行开发**：先定数据模型与 API 契约，三人同时开工，避免前后端互相等待。

> 比赛有明确的截止日期，第 1 周务必先把仓库、工程、云资源、API 契约定下来，这四件事是三人并行的前提。
