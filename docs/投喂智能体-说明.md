# 投喂智能体文档 · 使用说明

## 这三份是给智能体的，整份复制即可

| 文档 | 给谁 | 怎么用 |
| --- | --- | --- |
| `投喂智能体-A-后端与云架构.md` | 成员 A（后端与云架构） | 整份复制粘贴给 CodeArts 作为第一条指令 |
| `投喂智能体-B-AI与智能引擎.md` | 成员 B（AI 与智能引擎） | 同上 |
| `投喂智能体-C-前端与产品.md` | 成员 C（前端与产品） | 同上 |

**每份文档打开即是完整 Prompt，不需要从里面挑代码块。** 唯一要做的替换：B、C 文档里方括号或"若尚未建分支"的提示，按各自实际情况确认即可（A 的分支已建好）。

## 与执行包文档的区别

- `投喂智能体-*.md`：给智能体，整份粘贴，是行动指令。
- `01/02/03-成员*-执行包.md`：给人看，含完整分阶段任务清单和交付关系，供成员自己掌握全局、核对进度。
- 投喂文档已要求智能体自己去读执行包和规范文档，所以两者内容呼应、不冲突。

## 使用前提（务必先做）

1. 先用 CodeArts 打开仓库根目录（含 `.git` 的 `HarmonyICT` 文件夹）作为工作区。
2. 确认当前分支是自己的 feature 分支（A: `feature/backend-a`、B: `feature/ai-b`、C: `feature/frontend-c`）。
3. 本地 Git 身份与 SSH 已配置（见 `05-智能体协助Git拉取与推送说明.md`）。
4. 智能体需有终端/命令执行权限，否则无法建工程和跑 Git。

## 协作顺序提醒

A 的 Prompt 会产出 `database-design.md` 和 `api-specification.md` 两份契约——这是 B、C 并行开发的依据。建议 A 优先定稿这两份并发 PR 合入 develop，B、C review 后全面铺开，避免字段对不上的返工。
