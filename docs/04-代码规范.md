# NEXUS · 全员代码规范

> 适用全体成员与 CodeArts 代码智能体。**所有人在向 CodeArts 下发任务时，须在 Prompt 中要求「遵守 docs/04-代码规范.md」。**
> 优先级：本规范 > CodeArts 默认习惯。规范未覆盖处，遵循技术栈官方惯例。

---

## 1. 通用规范（前后端共用）

| 项 | 规范 |
| --- | --- |
| 编码 / 换行 | UTF-8（无 BOM），LF 换行，文件末尾保留一个空行 |
| 缩进 | 2 空格（前端 TS/JS/JSON）、4 空格（后端 Java）；禁止 Tab |
| 行宽 | 建议 ≤ 120 字符 |
| 文件命名 | 后端类：大驼峰 `WorldFactService.java`；前端组件/文件：小驼峰或短横线 `risk-card.tsx` / `useRisk.ts`，全项目统一取其一 |
| 注释语言 | 中文；公共 API / 复杂逻辑必须写清楚「为什么」，不只写「是什么」 |
| TODO | 统一格式 `// TODO(成员标记, 阶段): 说明`，如 `// TODO(A, 阶段二): 接入真实 OBS 回调` |
| 禁止 | 提交调试用 console.log/System.out、注释掉的死代码、无意义提交 |

**Git Commit**（与 `00-GitHub协作与整合约定.md` 一致）：`[A/B/C] 类型: 描述`
类型限于 `feat / fix / docs / refactor / test / chore`。示例：`[C] feat: 新增风险中心页面骨架`。

## 2. 后端规范（Java 21 + Spring Boot）

### 2.1 包结构（固定，不得随意新增顶层包）

```
com.nexus
├── common      # 统一响应 Result、异常、工具类
├── auth        # 认证与 JWT
├── user        # 用户资料与个人设置
├── world       # 个人世界模型（实体/事实/关系/事件/来源）
├── ingestion   # 文件接入与信息抽取调度
├── risk        # 风险分析引擎
├── decision    # 决策模拟引擎
├── agent       # Agent 编排与工具调用
├── asset       # 资产管理
├── task        # 任务与行动管理
├── ai          # AI Provider 接口与实现（A 只建接口，B 写实现）
└── api         # 应用启动与接口入口
```

### 2.2 分层与命名

| 层 | 后缀 | 说明 |
| --- | --- | --- |
| 控制层 | `Controller` | 只做参数接收与响应，不写业务逻辑 |
| 服务层 | `Service` / `ServiceImpl` | 业务逻辑归口 |
| 数据层 | `Mapper` / `Repository` | MyBatis-Plus |
| 实体 | `Entity`（`world_facts` → `WorldFact`） | 与表一一对应 |
| 传输对象 | `Request` / `Response` / `DTO` | 入参出参独立定义，禁止直接用 Entity 接收请求 |
| 常量/枚举 | `Constants` / `XxxEnum` | 集中管理，禁止魔法值 |

**方法命名**：查询 `get/list/find`，新增 `create/add`，修改 `update`，删除 `delete`，判断 `is/has`，转换 `toXxx`。

### 2.3 统一响应与异常

- 所有接口返回 `Result<T>`（`code / message / data / timestamp`），禁止直接返回裸对象或 Map。
- 业务异常统一抛 `BizException`，由全局异常处理器转 `Result`；禁止在 Controller 里 try-catch 后自行拼错误响应。
- 错误码集中定义在 `common` 的枚举里，按模块分段（如认证 1xxxx、世界模型 2xxxx）。

### 2.4 安全与数据隔离（红线）

- **所有用户业务表查询必须带 `user_id` 条件**，从 JWT 上下文取当前用户，禁止信任前端传入的 user_id。
- 文件上传校验类型与大小；路径不接受用户可控的相对路径穿越。
- 敏感信息（密钥、OBS AK/SK）只走配置或环境变量，禁止硬编码与提交。

### 2.5 其他

- 依赖注入用构造器注入，不用字段注入（`@RequiredArgsConstructor` 可接受）。
- 日志用 SLF4J（`log.info/debug/error`），带上下文（userId、factId），禁止 `System.out.println`。
- Controller 入参用 `@Valid` 校验，DTO 上标注校验注解。
- 分页统一封装（页码从 1 开始，带 total）。

## 3. 前端规范（Next.js + React + TypeScript）

### 3.1 目录结构（固定）

```
nexus-frontend/
├── app/                # Next.js App Router 页面与路由
├── components/         # 通用组件
│   └── <业务域>/        # 如 world/、risk/、agent/
├── hooks/              # 自定义 hooks（useXxx）
├── lib/ 或 services/   # API 请求封装、工具函数
├── types/              # 全局 TypeScript 类型定义
├── store/              # 状态管理（如使用）
├── styles/             # 全局样式
└── public/             # 静态资源
```

### 3.2 编码规范

- 严格 TypeScript：**禁止 `any`**（确有需要须注释说明并用 `unknown` + 收窄）；接口/类型优先用 `interface`。
- 组件用函数式组件 + Hooks，禁止 class 组件。
- 组件名大驼峰；文件名、hooks、变量、函数小驼峰；常量大写下划线。
- 一个组件单文件，超过约 200 行应拆分；重复的 UI 抽为组件，重复的取数抽为 hooks。
- Props 必须定义类型并解构；>`{}` 的宽泛类型禁止使用。
- 样式统一用 Tailwind 原子类；仅复杂动画/图表用 Framer Motion / ECharts，禁止散落的内联 style。
- 图片与静态资源走 `next/image`；列表 key 用稳定业务 id，禁止用数组下标。

### 3.3 API 与数据

- 所有请求统一走 `services/` 封装，组件内不直接写 fetch/axios。
- 响应类型与后端 `Result<T>` 对应，定义统一的类型包裹。
- **禁止写死虚假的动态数字或随机数据充场面**；Mock 数据须放在独立 mock 文件并标注，联调时替换。
- 错误统一处理（提示 + 错误码），禁止静默失败。

## 4. 数据库 / SQL 规范

- 表名、字段名全小写下划线（`world_facts`、`source_id`）；主键 `id`，外键 `<对象>_id`。
- 所有业务表必须有 `user_id`，并建立 `(user_id, ...)` 复合索引。
- 每表含 `created_at`、`updated_at`（时间戳）；事实表按契约含 `valid_from`、`valid_until`、`confidence`。
- DDL 变更写入迁移文件，纳入版本管理；禁止直接在云数据库手工改表而不落文档。
- 查询禁止 `SELECT *`，明确字段列表；批量操作注意索引命中。

## 5. API 契约规范（呼应 `api-specification.md`）

- RESTful 风格；资源名用复数名词，动作用子资源（如 `/agent/runs/{id}/execute`）。
- HTTP 方法：GET 查询、POST 新增、PUT/PATCH 修改、DELETE 删除。
- 统一前缀（如 `/api/v1`）；认证除登录注册外全部必需。
- 请求/响应字段名小驼峰，与前端类型一致；时间格式 ISO 8601。
- 错误码与错误说明写入契约文档，前后端共用同一份定义。

---

## 6. AI 模块规范（成员 B 专项）

- 业务层只依赖 `com.nexus.ai` 的 Provider 接口，禁止直接调用具体模型 SDK。
- 提示词集中管理成模板文件，禁止散落在代码中；每次调用的关键参数（模型、温度）走配置。
- 结构化输出必须按 `extraction-schema.md` 的 JSON Schema 校验后再入库；不符合的输出重试或标记低置信度。
- 每条事实写入 `source_id` 与 `confidence`；风险结论必须由规则/算法产生，模型仅做解释，禁止模型自由生成风险判断。
- Agent 操作分级 L0-L2，L2 操作须带用户授权记录与操作日志。
