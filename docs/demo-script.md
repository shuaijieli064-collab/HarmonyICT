# NEXUS · 演示脚本（V2 初稿）

> 用途：竞赛答辩现场按本脚本走完整闭环。每一步都标注**操作 / 讲解词 / 预期结果 / 证据留痕点**。
> 主线：上传资料 → 抽取入库 → 世界模型 → 风险发现 → 用户授权 → Agent 执行 → 结果回填。
> 初稿状态：V2；截图/录屏待现场录制后按 [`evidence/README.md`](evidence/README.md) 归档。

---

## 0. 演示前准备（3 分钟）

| 检查项 | 命令 / 动作 | 通过标准 |
|---|---|---|
| 后端就绪 | `curl http://localhost:8080/actuator/health` | 返回 `{"status":"UP"}` |
| 前端就绪 | 浏览器打开 `http://localhost:3000` | 驾驶舱渲染，无控制台报错 |
| 测试资料 | 准备 1 份笔记本发票 PDF + 1 份订阅记录 TXT + 1 份学习计划 TXT | 单文件 ≤ 20MB，扩展名在白名单内 |
| 演示账号 | 现场注册或复用测试账号并登录 | JWT 写入 localStorage，页面显示登录态 |

> 本地环境用 `local` profile（H2 + mock AI），无需云凭据即可跑通闭环；公网 Demo 用 `prod` profile 走真实华为云链路。

## 1. 开场（30 秒 · 讲解词）

> "NEXUS 是个人资料智能管家。每个人手里都有发票、订阅、计划这些零散资料，但很难回答'我现在有什么、接下来会发生什么、我该做什么'。我们用华为云把这条链路打通：上传资料，AI 抽取成可溯源的事实，规则引擎发现风险，用户授权后 Agent 把风险变成待办。下面我用一份真实资料走一遍完整闭环。"

## 2. 上传资料（1 分钟）

| 项 | 内容 |
|---|---|
| **操作** | 进入驾驶舱 → 上传区拖入笔记本发票 PDF → 观察两段进度（上传中 / AI 抽取中）→ 事实结果卡片出现 |
| **讲解词** | "上传走两段：先把原文件存到 OBS 拿到 sourceId，再异步调 OCR 和 MaaS 抽事实。前端按契约每 2 秒轮询一次，抽到事实就展示出来。注意这里每条事实都有置信度和来源。" |
| **预期结果** | 文件状态从「上传中」→「AI 抽取中」→「已完成」；下方出现 N 条事实，含 `objectValue`、置信度、`factStatus` 徽章 |
| **兜底演示** | 拖入一个 `.exe` 文件 → 立即被客户端白名单拦截并提示「不支持的文件类型」；这是上传兜底（不必真等后端 30102） |
| **证据留痕** | `docs/evidence/demo/20261126-v2-upload-截图.png` |

## 3. 世界模型（1 分钟）

| 项 | 内容 |
|---|---|
| **操作** | 导航到「世界模型」→ 查看力导向图谱（实体节点 + 事实节点）→ 展开「最近事实」列表核对置信度与可信状态 |
| **讲解词** | "抽取结果不是一堆散文本，而是落进 PostgreSQL 的实体-事实-来源三元组。图谱里大节点是实体，小节点是事实谓词和取值，每条事实都能点开看来源和置信度——这就是'可追溯'。" |
| **预期结果** | 图谱渲染出节点与连线；事实列表显示 `predicate: value`、置信度、`factStatus` 徽章；鼠标滚轮缩放、拖拽可用 |
| **边界说明** | 若为空态，显示"上传资料完成抽取或手动创建实体后，图谱将自动呈现"——演示时先完成第 2 步 |
| **证据留痕** | `docs/evidence/demo/20261126-v2-entity-graph-截图.png` |

## 4. 风险发现（1 分钟）

| 项 | 内容 |
|---|---|
| **操作** | 导航到「情报中心」→ 查看风险卡片（等级徽章 + 触发规则徽章 + 触发原因）→ 点击「查看风险依据」展开关联事实快照 |
| **讲解词** | "风险不是大模型随口说的。每条风险由规则引擎命中，卡片上直接标出触发规则和关联事实——比如订阅 30 天内续费，依据就是抽取出来的续费日期事实。模型只负责理解和解释，不下风险结论。" |
| **预期结果** | 至少 1 条 open 风险；展开后显示关联事实的谓词、取值、置信度、证据来源 |
| **交互** | 可演示「确认」/「解决」按钮改变风险状态（若演示数据允许） |
| **证据留痕** | `docs/evidence/demo/20261126-v2-risk-evidence-截图.png` |

## 5. Agent 授权执行（1.5 分钟 · 高潮）

| 项 | 内容 |
|---|---|
| **操作** | 导航到「Agent 中心」→ 发起执行并触发编排 → 刷新查看 run 详情与操作日志 → 找到 L2 待授权日志 → 点击「授权执行（L2）」→ **出现二次确认条** → 点击「确认授权」→ 观察任务列表刷新与执行结果 |
| **讲解词** | "这里是最关键的安全设计：Agent 只能做 L0 到 L2 的只读或建议类动作，L2 的内部操作必须用户显式授权。注意我点授权后不是立刻执行，而是弹出二次确认，明确告诉我'该操作将真实执行并写入任务/事实'。确认之后才执行，执行日志和生成待办都会回填到前端。" |
| **预期结果** | 二次确认条出现（含确认/取消）；确认后日志状态更新、任务列表新增待办；无支付/外部高风险动作 |
| **红线强调** | "全程没有支付、没有改外部账户、没有越权 user_id——这些是硬红线。" |
| **证据留痕** | `docs/evidence/demo/20261126-v2-agent-auth-录屏.mp4`（建议录屏，展示二次确认全过程） |

## 7. 演示节奏与风险预案

| 环节 | 时长 | 若失败 |
|---|---|---|
| 开场 | 30s | — |
| 上传 | 1min | mock 模式仍应出事实；若卡在抽取，切到已录制的截图讲解 |
| 世界模型 | 1min | 图谱空态时口述"先上传后展示"，切下一页 |
| 风险 | 1min | 无 open 风险时用预置演示数据或口述规则命中机制 |
| Agent 授权 | 1.5min | 二次确认是本环节核心，务必保留；后端不可用时用录屏 |
| 收尾 | 30s | — |

**合计约 5 分钟**，预留 2 分钟答疑。
